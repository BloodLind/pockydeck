## Transaction algorithm

`recordOnce` executes these steps inside one `RoomDatabase.withTransaction`:

1. Return `AlreadyRecorded` immediately when `operation_id` already exists.
2. Lazily insert state `(1, 0)` for a fresh v2 database; migrated databases
   already contain the max-history seed.
3. Read `last_open_order`, reject `Long.MAX_VALUE`, calculate `next = last + 1`,
   and conditionally update the expected counter row.
4. Insert the immutable operation receipt with abort-on-conflict.
5. Update history by item ID or perform an aborting insert when that item has no
   history row. The history primary key enforces one current record per item and
   its unique order index prevents ties.

Room serializes these write transactions on the shared database instance. Any
counter race, uniqueness violation, mapping error, or storage failure aborts
the counter update, receipt, and history write together. A newer operation for
the same item updates its one history row; older operation receipts remain for
durable deduplication.

## Constructor and integration API

```kotlin
val database = LauncherDatabase.open(applicationContext)
val successfulOpenRepository = RoomSuccessfulOpenRepository(database)
```

The repository exposes only the F01 `records` Flow and `recordOnce(candidate)`.
F07/F08 will pass a candidate only after
`AcknowledgedLaunchPolicy.acknowledge` returns one. Failed, internal, unknown,
and repeated acknowledgements produce no candidate and therefore no persistence
call. External dispatch remains a separate side effect and must never be
replayed to fill a missing local history record.
