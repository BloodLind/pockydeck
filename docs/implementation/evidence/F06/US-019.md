# US-019 evidence — durable preferences and navigation snapshots

## Delivered boundary

`LauncherPreferencesStore.open(context, fileName)` owns one application-scoped
Preferences DataStore on `Dispatchers.IO`. The default exact file name is
`handheld-launcher.preferences_pb`; callers must provide a non-blank leaf file
name ending in `.preferences_pb`. `close()` cancels and joins the owning job so
tests and future lifecycle owners cannot overlap two stores for the same file.

One store is shared by:

- `DataStoreControllerPreferenceRepository(store)`
- `DataStoreNavigationSnapshotRepository(store)`

The DataStore type stays internal to `core:data`. Both adapters expose only the
F01 domain repository ports. Debug variants also publish
`FakeControllerPreferenceRepository` and `FakeNavigationSnapshotRepository`.

## Reserved encoding

Controller mapping uses two strings:

- `controller.confirm_button`
- `controller.back_button`

Values are `a` or `b`. Missing, unknown, wrong-type, or same-button pairs decode
to typed `ConfirmBackMapping.Default` (A-confirm/B-back).

Each destination uses its stable `LauncherDestination.persistedKey` in
`navigation.<destination>.*` and stores version `1` with these exact suffixes:

| Suffix | Type | Meaning |
| --- | --- | --- |
| `version` | Int | Snapshot encoding version |
| `selected_item_id` | String | Optional stable selected `ItemId` |
| `first_visible_item_id` | String | Optional stable anchor `ItemId` |
| `first_visible_offset_px` | Int | Non-negative anchor offset |
| `query` | String | Query, including the empty value |
| `filter_key` | String | Optional stable `PageStateKey` |
| `sort_key` | String | Optional stable `PageStateKey` |

Saving is one DataStore edit. Null optional fields remove only their field, and
clearing removes only the seven keys for that destination. No enum ordinal,
Compose state, numeric list position, provider key, or collection is stored.

Known fields are decoded from their runtime value types. An absent, unknown, or
wrong-type version yields no snapshot for that destination. Invalid/blank
`ItemId` and `PageStateKey` values become null; a missing, negative, or
wrong-type offset becomes zero; missing/wrong-type query becomes empty. These
field-local fallbacks preserve other destinations and controller data.

An unreadable Preferences protobuf is handled by DataStore's corruption handler
and resets that DataStore file only. Room remains a separate database. Ordinary
read/write I/O exceptions are not caught or converted to success, so valid
storage is never erased for a normal I/O failure.

Application wiring must retain one `LauncherPreferencesStore` instance shared by
both repositories. F06 owns future changes to these key names, version meaning,
and corruption policy. This story makes no Room schema change: the accepted
Room version 2 and its explicit version 1-to-2 migration remain unchanged.
