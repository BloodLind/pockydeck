# US-020 Android component discovery evidence

- Baseline: `bc60032`
- Scope: Android 13 current-user `MAIN`/`LAUNCHER` discovery only

## Verified approach

`PackageManagerAndroidAppDiscovery` runs one
`PackageManager.queryIntentActivities(Intent(ACTION_MAIN).addCategory(CATEGORY_LAUNCHER),
ResolveInfoFlags.of(0))` query on its supplied coroutine dispatcher. Android documents this intent
pair as the launcher top-level list and documents `queryIntentActivities` as returning every matching
activity. Querying the process `PackageManager` scopes the result to the Android user running the
launcher. This intentionally avoids `LauncherApps`, whose result can contain synthesized activities,
and avoids installed-package enumeration.

Every accepted `ResolveInfo.activityInfo` becomes one `LibraryItem.AndroidApp`. Identity is the
existing `CurrentUserAndroidComponentId(packageName, activityClassName)`, so two activities in one
package remain separate. That same component ID is the icon reference for later presentation code;
US-020 performs no icon decoding or main-thread image load. Entries must be enabled at activity and
application level, exported, structurally valid, and outside the launcher's own package. Relative and
short Android class names are normalized before constructing the domain identity. Labels are read on
the discovery dispatcher and fall back to the activity class name. All accepted entries are available,
use category `OTHER`, and expose the existing Android-app action set. No category inference occurs.

A successful whole query produces `CatalogInventory.Complete(CurrentUserAndroid)`. Provider or
mapping failure produces an empty `Incomplete(FAILED)` inventory, which cannot infer removals under
the accepted catalog contract. Cancellation is rethrown for US-021 to record as `CANCELLED` while
preserving the cache.

Official Android references:

- [Intent API: `ACTION_MAIN` + `CATEGORY_LAUNCHER` is the launcher top-level list](https://developer.android.com/reference/android/content/Intent)
- [PackageManager API: `queryIntentActivities`](https://developer.android.com/reference/android/content/pm/PackageManager#queryIntentActivities(android.content.Intent,%20android.content.pm.PackageManager.ResolveInfoFlags))
- [Declare package visibility needs by intent signature](https://developer.android.com/training/package-visibility/declaring#intent-signature)

## Narrow production manifest delta

The coordinator reviewed and added only this package-visibility declaration to the application
manifest. It requests no Android permission:

```xml
<queries>
    <intent>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent>
</queries>
```

There is no `QUERY_ALL_PACKAGES`, ROM, network, overlay, accessibility, or usage access.

## Automated verification

- `:core:data:testDebugUnitTest --tests
  "dev.handheld.launcher.core.data.discovery.PackageManagerAndroidAppDiscoveryTest"` — passed.
  Seven JVM seam tests cover multiple activities in one package, stable component/icon references,
  class-name normalization, category and actions, self/disabled/unexported/malformed rejection,
  duplicate resolver rows, background-dispatcher execution, failure semantics, and cancellation.
- `:core:data:compileDebugAndroidTestKotlin` — passed. The Android fixture declares two concrete
  `MAIN`/`LAUNCHER` activities and one concrete app-details-only activity in the same test APK. The
  instrumented test queries the real Android `PackageManager`, requires both launcher components,
  rejects the details-only component, and checks package self-exclusion.
- The focused instrumented class passed all three tests on `emulator-5556`, Android 13 / API 33,
  model `Android SDK built for x86_64`. Its [inventory capture](US-020-emulator-inventory.txt) records
  both same-package fixture components, rejection of the details-only component, self exclusion, and
  11 external system launcher components returned through the app's real query. No physical-device
  package installation or untargeted connected test was performed.
