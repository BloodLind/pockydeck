# US-021 cache-first Android reconciliation evidence

- Baseline: `bc60032` plus accepted US-020
- Device verification: `emulator-5556`, Android 13 / API 33

## Public consumer boundary

`AndroidCatalogRefreshCoordinator` receives the accepted `CatalogRepository`, US-020
`AndroidAppDiscovery`, an `AndroidPackageChangeMonitor`, and an application-owned `CoroutineScope`.
It exposes:

- `catalog: Flow<CatalogSnapshot>` as the direct Room flow, with no scan prerequisite;
- `refreshState: StateFlow<AndroidCatalogRefreshState>` with `Idle`, `Refreshing`, `Ready`, and
  `Error` states;
- `state: Flow<AndroidCatalogState>` pairing the retained snapshot with refresh state for Home;
- idempotent `start()` and `stop()` package-listener hooks, `onResume()` convergence, and explicit
  `refresh()`.

Home integration calls `start()` when it becomes active and immediately calls `onResume()`. That
initial pair produces one startup scan. `stop()` unregisters package callbacks and clears the one-shot
resume suppression; a later `start()` plus `onResume()` always queues convergence, including while an
older slow scan is still finishing.

The coordinator reads `CatalogRepository.snapshot.first()` before starting its first enumeration.
Consumers can collect the same cold Room flow immediately and keep browsing its cached rows. One
application-scope worker consumes a conflated trigger channel, so requests overlap into at most one
pending scan and never run reconciliation concurrently. Lifecycle stop does not replace or cancel
that worker, which prevents stop/start generations from racing status writes.

Complete inventories use the accepted repository transaction and therefore update discovered fields,
mark omitted Android components unavailable, and restore them under the same stable ID when
rediscovered. Incomplete `FAILED`, `PARTIAL`, and `CANCELLED` inventories update status only. A
provider cancellation is recorded non-destructively; cancellation of the owning worker is recorded in
`NonCancellable` cleanup and then rethrown rather than swallowed.

`BroadcastAndroidPackageChangeMonitor` registers only while active for protected system
`PACKAGE_ADDED`, `PACKAGE_REMOVED`, `PACKAGE_CHANGED`, and `PACKAGE_REPLACED` broadcasts with the
`package` data scheme. It uses `RECEIVER_NOT_EXPORTED`, appropriate for broadcasts from the system UID,
and adds no manifest receiver or permission. Android notes that context receivers exist between
registration and unregistration, and documents these package broadcasts as system-protected:

- [Android broadcast receiver lifecycle and export flags](https://developer.android.com/develop/background-work/background-tasks/broadcasts#context-registered-receivers)
- [Android Intent package-change broadcasts](https://developer.android.com/reference/android/content/Intent#ACTION_PACKAGE_CHANGED)

Debug `AndroidCatalogStateFixtures` supplies initial-empty loading, retained-cache refreshing, and
retained-cache failure states for F08/Home previews and tests.

## Acceptance mapping

- AC-01: cached state remained observable while a gated scan was `Refreshing`; failed scan kept the
  cache and published `Error(FAILED)`.
- AC-02: partial payload and cancellation tests preserved cached items and stored incomplete status;
  neither could mark the inventory complete.
- AC-03: 20 package callbacks plus 20 explicit requests during a gated scan produced one follow-up
  scan, maximum concurrency one. Stop/immediate-start also retained one owner.
- AC-04: fake install/update/removal/resume convergence passed; a slow pre-stop scan plus missed
  inactive change queued a second resume scan. Real Room verification preserved all user references
  through removal and rediscovery.
- AC-05: the direct cache flow, combined state flow, four refresh hooks, and three debug fixture states
  are available to F08 without awaiting discovery.

## Coordinator-owned integration delta

Construct one application-lifetime `CoroutineScope(SupervisorJob() + Dispatchers.Default)`,
`PackageManagerAndroidAppDiscovery`, `BroadcastAndroidPackageChangeMonitor`, and
`AndroidCatalogRefreshCoordinator` in `AppContainer`. F08 can bind the lifecycle hooks and collect
`state`. No domain, Room schema, Gradle, storage-format, manifest, or permission change is required.
