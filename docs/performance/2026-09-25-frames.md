# Flip 2 frame audit — 2026-09-25

Measured on the Retroid Pocket Flip2, Android 13, 1920×1080 at 60 Hz, launcher scale 110%. Library contained 3,768 items; Apps used its existing 20-item Other filter. Home artwork background and the user's appearance preferences were retained. No games were launched or app data cleared.

## Changes verified

- Collection cover ordering now observes viewport changes in a separate composition scope. The header and grid host no longer recompose just to resequence visible covers. Native regression coverage scrolls forward/backward and checks both composition counts and the order of admission.
- Card focus lift now reads animation state during placement and drawing. Focus animation no longer recomposes the card every frame. Native tests preserve immediate focus outlines, fixed allocations, and reduced-motion behavior.
- Added `scripts/performance/measure_frames.py`, which saves frame counters, memory, battery temperature, app exit history, build flags, and compilation mode. It verifies the app is foreground before issuing gestures.

## Initial release measurements

These runs used the signed, non-debuggable release APK before correcting incremental installation/compilation. They are retained as a comparison, not the final device configuration.

| Scenario | Frames | Missed deadlines | p95 | p99 |
| --- | ---: | ---: | ---: | ---: |
| Home horizontal scrolling | 588 | 8 / 1.36% | 18 ms | 21 ms |
| Library grid scrolling | 513 | 25 / 4.87% | 21 ms | 29 ms |
| Library list scrolling | 534 | 7 / 1.31% | 18 ms | 19 ms |
| Apps scrolling | 498 | 10 / 2.01% | 17 ms | 23 ms |
| 48 dock taps across Home/Library/Apps/Favorites/Settings | 694 | 51 / 7.35% | 65 ms | 97 ms |

A second page-switch run gave 65 ms p95, 93 ms p99, and 7.77% missed deadlines. No slow bitmap uploads were reported. Entry into collection pages had the largest stalls; main-thread composition/layout is a stronger suspect than texture upload, though these counters are not a CPU call-stack trace.

Debug before/after measurements were mixed and do **not** establish a general speedup from the two source changes: Library grid p95 was 34→40 ms, list 20→20 ms, Home 18→21 ms, Apps 18→19 ms, and dock 73→77 ms. The recomposition regression test establishes the structural improvement; it should not be presented as a measured FPS gain.

## Final installation and remaining bottleneck

The initial incremental installation continued to report `run-from-apk` despite successful compile commands. Reinstalled the same release APK with `--no-incremental -r`, preserving app data, and ran `cmd package compile -m speed -f dev.handheld.launcher`. Package inspection then confirmed `arm64: [status=speed] [reason=cmdline]` and no DEBUGGABLE flag.

The repeated 48-tap route still produced 699 frames with 62 missed deadlines (8.87%), p95 81 ms and p99 150 ms. Full compilation therefore did **not** demonstrate an improvement to page transitions. Memory afterward was about 163 MiB PSS with one Activity. The main unresolved performance issue is page entry, not sustained scrolling or reported bitmap uploads. There is no basis to claim locked 60 FPS.

Next priorities are a native CPU/frame trace of collection-page entry, then reducing the measured initial composition/measurement work while preserving cover buffers and controller focus. Avoid retaining every page and its images merely to hide entry cost. Baseline-profile/release tuning should be evaluated with repeated equal-compilation-state runs after the page-entry work is addressed.

The validated full release installation remains on the handheld. Local signed APK: `.local/frame-stability-release.apk`; SHA-256: `C00BFF39FAD6608382E50B2EE067D07B7EAB2336B582BAC4F7099D9612F29927`. It uses the existing development certificate, version 0.10.3/code 17; this audit did not publish a release.

## Stability checks

All 181 app and 12 design-system JVM tests passed. Debug/release builds and lint passed (zero errors, 15 existing warnings). Eight debug device checks passed for viewport composition, cover ordering, grid/list behavior, held input, and focus/reduced motion. Two actual-release checks passed for touch/controller focus and held D-pad navigation, reversal, acceleration, and release without queued movement.

The release held-search check recorded 909 frames: p95 17 ms, maximum 48 ms, none over 50 ms. These instrumented FrameMetrics numbers are separate from the uninstrumented `gfxinfo` table. The test deliberately cleared decoded ROM artwork before holding directions.

No launcher crash or ANR was recorded during these runs; recorded process exits were install/test force-stops. Initial release memory snapshots were approximately 186–275 MiB PSS and retained one Activity; after 48 tab taps PSS was about 199 MiB. Battery temperature stayed around 26.5–26.7°C. This short check is not a long-duration leak or thermal soak test.

## Reproducing measurements

Use the same catalog, filter, sort, viewport, scale, and background settings. Choose the page before running; verify coordinates on any other screen size. Each scroll sample warms forward/return gestures, then records three cycles of two forward and two reverse 350 ms swipes, with a 400 ms pause. The script resets frame counters only. Tab runs warm one full route, then record six routes.

```powershell
python scripts/performance/measure_frames.py --adb D:/platform-tools/adb.exe --serial DEVICE_SERIAL --swipes 1100 720 1100 270 1100 300 1100 750 --output .local/frames-grid
python scripts/performance/measure_frames.py --adb D:/platform-tools/adb.exe --serial DEVICE_SERIAL --swipes 400 720 400 270 400 300 400 750 --output .local/frames-list
python scripts/performance/measure_frames.py --adb D:/platform-tools/adb.exe --serial DEVICE_SERIAL --swipes 1550 565 400 565 400 565 1550 565 --output .local/frames-home
python scripts/performance/measure_frames.py --adb D:/platform-tools/adb.exe --serial DEVICE_SERIAL --tabs 667 781 895 1009 1123 895 781 667 --cycles 6 --output .local/frames-tabs
```

Apps uses the grid gesture. Before Library samples, select PSP then All to start from the same first row; return to the original layout afterward. Raw captures for this audit are in ignored `.local/perf-*` files/directories. `gfxinfo` provides duration histograms and Android's own deadline classification, not a direct FPS counter. Single local runs show relative behavior and remaining stalls, not a universal 60 FPS guarantee.
